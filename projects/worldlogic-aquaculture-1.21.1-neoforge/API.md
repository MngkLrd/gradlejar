# Aqua integration (1.21.1 NeoForge)
Aqua owns actual fish/roe and marine population/lifecycle, fishing traits and species-specific AI. Core owns climate, water classification, river advection and PhysicalMaterials. Required Core 1.5.1, API revision >=21; core material revision >=2. 
- `WorldLogicApi.riverCurrent` supplies velocity in m/s; absent is undirected/unknown. Aqua chooses active swim direction and habitat preferences, never applies duplicate drift.
- `PhysicalMaterials` per-catch mass in kg, count-one pure provider; unknown mass stays unknown. Existing catch IDs unchanged.
- Optional Trauma API v1, public reportInjury only, fallback one vanilla damage call; no private NBT.
- Food processing and public edible serving contract (#259): `dev.minemods.aquaculture.api.AquaApi` API_VERSION=1, API_REVISION=0. `foodPortion(ItemStack)` returns `Optional<FoodPortion>` with `speciesId` (Aqua species ID), `edibleMassGrams` (int, per one item), `preparation` (RAW or COOKED). Read-only and thread-safe for an immutable/non-mutating caller stack, no server world access. Empty for whole catches, other items, missing/invalid mass or missing FOOD. `FOOD_PORTION` typed Core capability registered in common setup, id `worldlogic_aqua:food_portion`, version 1 rev0, interface FoodContract. `WorldLogicCapabilities.find(AquaApi.FOOD_PORTION,0)` when Aqua is available. Consumers can use optional class linkage or guarded public API reflection. Actual portion IDs `aquaculture:raw_<species>_portion` and `aquaculture:cooked_<species>_portion`. 100 g raw serving or exact remainder; cooked mass is floor(0.8*raw grams), minimum 1 g. Stack count is NOT the serving mass. Species-specific yield game estimates 40–60% of validated catch mass. Ordinary item FOOD completion only; do not reportFoodIntake again. Metabolism owns nutrient profiles, risk and energy, no calories/energy/toxin on catching, cutting or cooking. Core PhysicalMaterials receives exact portion mass (kg), raw nominal tissue; cooked composition unknown. Core processing catalog registers actual cutting instructions with variable yield. No hard Metabolism dependency.
