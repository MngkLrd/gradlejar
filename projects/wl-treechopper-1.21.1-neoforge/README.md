# WorldLogic TreeChopper 0.5.4 — development candidate
Minecraft 1.21.1 / NeoForge 21.1.262 / Java 21. Four persisted notch depths with matching collision and generated vanilla-textured models, variable axe hits, opposite-face felling advantage, a stump and a 36-tick rigid pivot animation via vanilla block displays. Eight vanilla log types. Initial recognizer is intentionally conservative: straight, isolated single-column trunks with a natural nonpersistent crown; branching/multitrunk/custom Terrarian trees are not supported yet. A placed replica of a natural tree can still be recognized; placement provenance is not tracked. One log is consumed in the stump; upper logs become items, leaves are decorative and do not drop. Animation is kinematic, without swept collision, damage or fallen-log placement. Core and HP public API v1 read-only bridges adjust hit quality and cooldown using remaining stamina and the actual main/support arm function. No independent fatigue counter or explicit additional exertion debit: Core's BreakEvent listener already charges effort. Existing per-piece protection events can still charge Core for individual logs/leaves; this requires a shared protection-only API or Core event-side coordination before claiming exact balance. Terrarian straight vanilla-species trees on dirt, mud or clay are supported by the recognizer; its custom larch/willow and branched forms are not yet supported. Integration APIs have not been tested with the actual dependent JARs. Standalone neutral fallback and pure effort formula are exercised in the server scenario. NeoForge protocol player backend is unsupported by the shared runner: QA uses the same server left-click event with FakePlayer, operator-only QA command. No client validation or save/reload test claimed.

0.5.1 regression fix: vanilla BreakEvent bypass blocked (synthetic protection event explicitly scoped); empty-hand natural-tree hit blocked; bounded connected tree discovery covers diagonal/forked crowns and sand substrate; four approach sides resolved from player position for existing cuts. All 13 currently registered Terrarian species have optional matching notch/stump assets and original log drops, using Terrarian's own bark/end textures (no copied art); custom loot tables are conditional on Terrarian being present. Independently rooted multi-column trees still excluded; unsupported recognition falls back to vanilla to avoid destroying structures. No provenance, sweep collision or actual client network/render test. Standalone FakePlayer exercises real gameMode.destroyBlock as a negative control and a branched fixture; integrated custom tree behavior not yet executed.

0.5.2 owner-approved temporary progression: bare hands and non-axe tools use vanilla single-block mining, including partially notched logs. Only axes are intercepted and blocked from bypassing the notch on recognized trees. Prior 0.5.1 bare-hand restriction is superseded. No new materials, crafting recipes, or progression rules. Regression asserts actual server destroyBlock success with bare hands, upper log remains, and actual destroyBlock rejection with axe both before and after the notch. Existing recognition limits remain.
0.5.3: no accepted zero-depth strikes; sound and durability only on changed block state. A fully severed but protected hinge retries without a phantom strike. Existing stump mesh reused as a visual-only upper cap, preserving the top of the cut block without creating a duplicate log item. Edge hinge and end-of-fall settlement align the cap with the adjacent horizontal trunk and the flat local ground plane. Old in-flight displays retain old pose math. No new art or textures. Real terrain sweep/uneven-ground support, persistent fallen-tree processing and three sequential bucking points are deferred per owner permission; animation still produces item drops. Server tests cover same-face progress, cap lifetime, stump and four-direction transform geometry; graphical client evidence remains unverified.

0.5.4: client-only attack input interception and held-target retention over the notch, serverbound strike request, server validation of reach/aim/tool/mode, existing server cooldown and authoritative swing only on actual cut. Vanilla mining continues for hands and nonrecognized blocks. New 12px upper-log display model for each species, using the existing log textures with cropped native UVs (no PNG changes); the real 4px stump remains, the falling upper segment touches the next log and starts flush with the stump, no extra yield. Prior in-flight entities retain legacy cap/pivot math. FakePlayer tests exercise the packet handler's server path, not actual network transport or first-person rendering. Actual client visual/held-button validation and integrated Core/Terrarian/HP tests still NOT_RUN; three-point persistent processing and terrain collision deferred.
