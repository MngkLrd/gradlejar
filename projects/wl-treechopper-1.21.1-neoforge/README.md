# WorldLogic TreeChopper 0.6.5 — development candidate
Minecraft 1.21.1 / NeoForge 21.1.262 / Java 21. Four persisted notch depths with matching collision and generated vanilla-textured models, variable axe hits, opposite-face felling advantage, a stump and a 36-tick rigid pivot animation via vanilla block displays. Eight vanilla log types. Initial recognizer is intentionally conservative: straight, isolated single-column trunks with a natural nonpersistent crown; branching/multitrunk/custom Terrarian trees are not supported yet. A placed replica of a natural tree can still be recognized; placement provenance is not tracked. One log is consumed in the stump; upper logs become items, leaves are decorative and do not drop. Animation is kinematic, without swept collision, damage or fallen-log placement. Core and HP public API v1 read-only bridges adjust hit quality and cooldown using remaining stamina and the actual main/support arm function. No independent fatigue counter or explicit additional exertion debit: Core's BreakEvent listener already charges effort. Existing per-piece protection events can still charge Core for individual logs/leaves; this requires a shared protection-only API or Core event-side coordination before claiming exact balance. Terrarian straight vanilla-species trees on dirt, mud or clay are supported by the recognizer; its custom larch/willow and branched forms are not yet supported. Integration APIs have not been tested with the actual dependent JARs. Standalone neutral fallback and pure effort formula are exercised in the server scenario. NeoForge protocol player backend is unsupported by the shared runner: QA uses the same server left-click event with FakePlayer, operator-only QA command. No client validation or save/reload test claimed.
