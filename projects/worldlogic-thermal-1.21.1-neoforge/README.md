# WorldLogic Thermal Dynamics 0.4.0-rc1
Minecraft 1.21.1 / NeoForge 21.1.262 / Java 21 / Gradle 9.2.1 / official mappings. Requires WorldLogic RC21 or later (API revision 2); build and production fixture pin published RC21 SHA-256. No Forge. Server and client must use this same Thermal version (payload 3).
Three pages replace the inventory while open: Body, Weather, Journal. HUD retains only meaningful temperature numbers and directional trend, no silhouette or ambiguous unlabeled squares; smooth color scale. Weather shows authoritative live API fields, modeled climate reference and clear-day estimate, never annual climatology (seasons not implemented). No experimental RC22 weather preview used. Outdoor wind is an estimate, sheltered wind is a bounded local approximation. Relative humidity moderates evaporation; cold and hot condition logic and Trauma-compatible damage retained.
Journal records own route each 200 active server ticks (10s at 20 TPS); up to 840 points and last seven elapsed game-time days. Each sample has world day/time, dimension, biome, coordinates, air, perceived and body temperature. No extrapolation across time gaps, changes of dimension or large teleports. Saved in player persistent data, retained after death; no data before installation. Server sends bounded history only to its owner on initial active update and new sample. Offline time does not create samples. Client GUI, true network player and joint Trauma remain not certified by server fixtures. No custom Trauma named condition API available; existing damage event compatibility remains. Gear moisture and hot food integration remain unavailable.
