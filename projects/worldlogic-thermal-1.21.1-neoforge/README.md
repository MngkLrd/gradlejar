# WorldLogic: Thermal Dynamics 0.3.1-rc1
Minecraft 1.21.1 / NeoForge 21.1.262 compile/QA baseline / Java 21 / Gradle 9.2.1 / Mojang mappings.
Core dependency: WorldLogic RC20, public WorldLogicApi v1. The build downloads and checks the published core SHA-256, or accepts the same file via -PworldlogicJar. Never embeds core classes. Run gradle clean build; the candidate is build/libs/worldlogic_thermal-neoforge-mc1.21.1-0.3.1-rc1.jar.
The core owns ambient climate, weather and fatigue; the addon calls environment once per second and addExertion, never reads or writes core private NBT. The core API does not expose gear moisture or hot food deadlines, so skin moisture is tracked independently and hot-food thermal contribution is disabled pending a public contract. Existing core food/wet gear mechanics are untouched. Wind speed is an addon approximation, not the regional climate direction vector. Radiant sources are sampled locally with line of sight. Survival only, own persistent temperature, no client authority.
Development PR, not approved for release. Server fixture tests use NeoForge FakePlayer, not network player interactions. Actual client HUD/inventory and multiplayer sync, world save/reload, real-player immersion and damage need separate validation. The 21.1.80 metadata minimum is provisional, not validated; CI uses 21.1.262. Do not claim full QA or release solely from compilation.

0.3.1-rc1: inventory side panel if room permits; fallback screen draws background once without blur, thermal HUD no anatomy silhouette. Separate thermal conditions progress after 30 consecutive critical seconds; sunstroke additionally requires direct solar exposure. One custom physiological damage event every ten seconds after onset, bypassing armor because clothing has already affected heat exchange. Trauma RC5's existing LivingDamageEvent.Pre handler routes non-physical damage to chest without bleeding/fractures. No private Trauma access or required addon. A dedicated named Trauma condition UI is not part of this build; the public ThermalApi exposes the condition for future medical integrations. Joint Trauma runtime and client rendering remain unverified until separately tested. RC20 core lock retained for compatibility; RC21 additive API not required.
