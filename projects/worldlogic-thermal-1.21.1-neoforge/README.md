# WorldLogic Thermal Dynamics 0.6.0-rc1
Minecraft 1.21.1 / NeoForge 21.1.262 / Java 21 / Gradle 9.2.1 / official mappings. Requires WorldLogic RC21 or later (API revision 2); build and production fixture pin published RC21 SHA-256. No Forge. Server and client must use this same Thermal version (payload 3).
Three pages replace the inventory while open: Body, Weather, Journal. HUD retains only meaningful temperature numbers and directional trend, no silhouette or ambiguous unlabeled squares; smooth color scale. Weather shows authoritative live API fields, modeled climate reference and clear-day estimate, never annual climatology (seasons not implemented). No experimental RC22 weather preview used. Outdoor wind is an estimate, sheltered wind is a bounded local approximation. Relative humidity moderates evaporation; cold and hot condition logic and Trauma-compatible damage retained.
Journal records own route each 200 active server ticks (10s at 20 TPS); up to 840 points and last seven elapsed game-time days. Each sample has world day/time, dimension, biome, coordinates, air, perceived and body temperature. No extrapolation across time gaps, changes of dimension or large teleports. Saved in player persistent data, retained after death; no data before installation. Server sends bounded history only to its owner on initial active update and new sample. Offline time does not create samples. Client GUI, true network player and joint Trauma remain not certified by server fixtures. No custom Trauma named condition API available; existing damage event compatibility remains. Gear moisture and hot food integration remain unavailable.

Body values use absolute condition colors and separate direction marks from consecutive fresh snapshots; small body trends down to 0.02 C/min are visible. No invented measurements.

0.5.0 candidate: core RC22 build/QA pin, runtime minimum remains RC21. Rebalanced cold target, campfire radiation, lantern and furnace. Plant fiber recipes accept extensible worldlogic_thermal:fiber_plants tag (vanilla grass/fern/dead bush/wheat; no confirmed Terrarian IDs). Six wearable pieces use vanilla leather armor rendering temporarily; two new blocks use vanilla material textures. Clay hearth requires coal/charcoal per 3600 ticks; evaporative cooler requires water bucket per 6000 ticks, stronger in dry heat and under shelter. No free room heating, no changes to core ambient. Village/igloo placement not implemented; no retroactive modification of existing structures. Sources: Naturmuseum Südtirol Ötzi grass remains, Alta Museum Sámi footwear, Horniman Museum qulliq, evaporative cooling historical principle. Runtime visual, real crafting interactions, fuel expiry, all clothing variants and joint addon tests still need evidence. Fixture QA exercises activation directly, not player bucket/coal interaction.

Bare-handed right-click collects two fibers from tagged grass/fern/dead bush blocks, consumes the plant, and leaves normal shears/harvest behavior available. Block and item tags are explicit optional integration points for Terrarian. No guessed item IDs.

0.6.0: primitive processing on a real stone surface (tag worldlogic_thermal:fiber_surfaces). Gather raw bundle bare handed or craft from a tagged plant; place via right click. Left click targets one of 64 cells, stone scraper processes a five-cell cross and consumes durability only on a productive hit. A completed surface gives four fibers on next click; shift-left retrieves partial material, preserving exact mask in item custom data. Block entity saves and syncs mask; removing support drops work. Thread and woven cloth recipes replace direct fiber clothing recipes. No quality grades yet: completion is required, not randomized. Visuals use vanilla moss/hay texture regions and placeholder inventory icons; actual client rendering and live packet interaction remain untested. Village/igloo placement remains outside this iteration. No changes to shared CI or other addons.

0.6.1-rc1: dedicated WL: Temperature creative tab with hearth icon; all thirteen registered item types, no injection into vanilla tools tab. Server verifies tab registration and item membership; client tab rendering requires client evidence. Gameplay mechanics unchanged from 0.6.0.
