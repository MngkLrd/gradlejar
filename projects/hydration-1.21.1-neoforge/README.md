# WL: Hydration 0.5.1 development candidate
Empty main/off hand: right click water to drink 250 mB. Vessel in main hand: aim at a source and right click to fill in one action; otherwise hold right click to drink 250 mB. Sneak-right click with another vessel in offhand to transfer main to offhand up to capacity. Sneak-right click with charcoal filter offhand treats up to 3000 mB, consuming one filter. Sneak-right click lit campfire with heatproof vessel to boil; offhand copper condenser selects distillation. Stay within four blocks and keep vessel unchanged in main hand; interrupted treatment produces no output. Boiling evaporates 5%, preserves modeled salt, distillation yields 70% with removed brine abstracted as waste. Composite contamination risk, not separate real pathogens and sediment. All numbers are gameplay tuning. No actual placed vessel or Fluid API bridge yet. RC28 API baseline; RC29+ native sources not independently tested. Existing Temperature and Trauma optional bridges retained. Dedicated creative tab. No release without production QA; current shared CI needs pinned Core JAR dependency. Visual QA required for custom pixel assets.

0.5.0: Core API v1 revision >=8 (RC29+); integration branch pins Core RC32 commit 792edd46f860047331a802f95f47ec3c85d3db45 for pack testing without modifying the Core branch. Positional water profile is captured at ingestion/filling/intake, including eight native waters. Storage aging uses overworld game ticks, open cup/basin/collector/filter/intake versus protected vessels/barrel/bottles; protected is slower, not sterile. Old NBT gets a new observation timestamp, not guessed elapsed age. Unloaded storage ages when accessed or next updated; no offline real-time aging. Quality affects absorbed gain, numerical salt can reduce or reverse gain; exposure adds fallback fluid loss when no medical API exists. Electrolyte index 0..100 (50 balanced), loss/food correction, stage thresholds 70/50/25/10. Parameters are gameplay tuning, not medical or chemical measurements. Core aggregate contamination does not distinguish pathogens and chemicals. Vanilla/Core buckets outside Hydration do not carry positional contamination. No Fluid capability, temperature or new textures in this iteration. API revision 2 adds physiology(), keeps old status() shape. Trauma optional API contract: static void reportWaterIntake(ServerPlayer,int volumeMb,double contaminationRisk,double salinityGkg); static double fluidLossPointsPerSecond(ServerPlayer), non-bleeding disease loss only, game points/sec; Trauma owns disease and does not write Hydration or count sweat or bleeding twice. Hydration calls intake once per actual consumed dose and reads disease loss once per second; missing/failing API falls back to local exposure penalty. Actual client/medical integration and production pack QA pending.
