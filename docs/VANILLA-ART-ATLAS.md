# Vanilla art reference atlas — working research notes

Under [Visual QA](VISUAL-QA.md) and [research evidence](VANILLA-RESEARCH.md). Official Minecraft Java 1.21.1, client SHA-1 30c73b1c5da787909b2f73340419fdf13b9def88. Nineteen actual source textures visually inspected and hashes confirmed. This is a practical interpretation of observed art, not official Mojang instructions, a universal drawing algorithm or an automatic review.

Use texture IDs relative to assets/minecraft/textures. Open actual verified PNGs at 1x and nearest-neighbor enlargement before drawing. Use the existing art_compare tool, official local client or version-pinned mirror verified against the official client. Do not redistribute vanilla PNGs. For tint/overlay art inspect the actual rendered reference when necessary; base grayscale and in-game color are different evidence.

Reference scope: these are observations of the listed 19 images, not every asset in the corpus. Vessel, food, tools, GUI, particles, entity UVs, animation and additional materials need direct visual study before adding recipes; R3 perturbation source selection does not imply visual inspection. Do not invent acceptance thresholds from summary statistics. If a candidate family is not covered, select and inspect actual comparable vanilla references using Visual QA.

## Handoff for the independent reviewer

Use `tools.qa.vanilla_benchmark` privately with a fresh seed; give a fresh reviewer only the rendered A/B sheets and instructions, no source key, filenames, metrics, author findings or seed. Ask for A/B/UNSURE source choice and separate specific material/shape/cluster/light observations and aesthetic accept/reject/unsure for each image. Freeze responses before revealing the key. Source identification accuracy is not aesthetic accuracy. For real product judgments, add owner-rejected and owner-approved assets with exact hashes; include difficult good-faith art, not just obvious synthetic shuffles.
