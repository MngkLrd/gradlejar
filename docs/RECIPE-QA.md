# Recipe discovery and generated QA

Build Hub automatically discovers recipes from every successfully compiled enrolled JAR and uploads the machine-readable inventory and generated candidates as a separate advisory artifact. For local generation run `python -m tools.qa.recipe_qa path/to/final.jar --minecraft 1.21.1 --loader fabric --out recipe-qa` on the actual compiled JAR. Reads singular/plural recipe resource folders, reports actual IDs, hashes the JAR, classifies concrete shaped/shapeless grids, emits a schema-1 player suite per supported vanilla-ID recipe. Each generated suite starts from fixtures, verifies output absence and exact inputs, clicks grid slots, verifies output count and input consumption. It is NOT_RUN until attached to the appropriate executable profile and actually executed; merge compatible scenarios into the mod-specific suite respecting the action/wait budget. Use a fresh isolated fixture; don't blindly append to other tests. No /give result. Vanilla recipe ID availability and overrides are verified only by real runtime, not by parsing. Tags, alternatives, conditions, custom result data and non-grid recipes need specific adapters or an explicit test. New modded IDs need a real modded registry client or loader-native GameTest (not proof of player UI). The generated manifest distinguishes these instead of skipping them silently.

## Efficient iteration

`@changed:<exact-base-commit-sha>` is an explicit Build Hub dispatch selector for only the projects affected since that commit. It uses the same full diff planner, shared-source and scenario invalidation rules as normal pushes. It does not reuse unverified binaries or bypass complete-cohort packaging; use complete cohorts for complete releases.

[Visual QA](VISUAL-QA.md) emits `redraw-queue.json` with hash-bound review tasks grouped by identical PNGs. The agent reviews actual warnings against the Blockbench guide, makes one targeted correction if needed, and reruns the visual check. Heuristics alone are not authorization to recolor art. No CI image-generation service or graphical modded client is implemented in this iteration; runtime registry and GUI tests are a distinct backend.
